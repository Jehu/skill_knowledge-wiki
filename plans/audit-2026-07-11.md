# Knowledge Wiki Skill Audit

Date: 2026-07-11  
Baseline: commit `994e4f6` plus the staged and untracked working-tree changes listed in the audit session (`SKILL.md`, `scripts/auto_ingest.py`, `scripts/ingest_source.py`, `scripts/wiki_core.py`, `scripts/wiki_log.py`, and untracked `scripts/fetch_render.js`)
Scope: tracked project files plus the baseline changes named above; `.venv`, ignored runtime state, and unrelated untracked files were excluded
Mode: standard, read-only source audit

## Executive assessment

The skill has a coherent product boundary and unusually useful operational knowledge, but it is not yet safely portable. The highest-leverage work is to close two unsafe filesystem behaviors with focused regression tests, establish a broader verification baseline in parallel, and remove the personal filesystem layout from the packaged configuration.

## Recommended order

1. Ship finding 2 with focused tests proving caller-owned image directories are preserved.
2. Ship finding 3 with focused containment tests for every category-derived path.
3. Ship finding 4 independently or alongside the safety fixes; it has no dependency on them.
4. Expand the focused tests into the broader verification baseline from finding 1.
5. Refactor `SKILL.md`: keep routing, invariants, canonical commands, and live pitfalls; delete duplicated incident history and move only unique, still-actionable knowledge.
6. Classify broad exception handlers, then tighten verified harmful ingest and transcript paths incrementally under tests.

Dependency note: the focused slices of finding 1 land with findings 2 and 3. The broader baseline and finding 4 are independently deliverable. Finding 6 depends on relevant characterization coverage, not completion of the entire baseline.

## Direction options

- **Later bet: make the skill self-validating.** Consider a small offline `scripts/skill_doctor.py` only if setup incidents continue after the configuration and validation fixes. Start with configuration resolution and wiki-root writability; add dependency, Ollama, or browser probes only when repeated operator failures justify the maintenance surface.
- **Separate agent routing from operator troubleshooting.** Keep `SKILL.md` compact and link to focused references for Substack, YouTube, email, and recovery scenarios. The repository already has those references, so this mainly removes duplication and lowers instruction ambiguity.

## Considered and rejected

- Direct user-invoked URL fetching was not reported as SSRF because selecting the destination is the CLI's purpose. This rejection does not cover unattended RSS entries, redirects, email assets, or other remotely supplied URLs; those cross a separate trust boundary and require dedicated review and outbound URL controls.
- Subprocess use was not reported as command injection: inspected calls use argument arrays and do not set `shell=True`.
- Unpinned dependency upper bounds were not prioritized without evidence of a current incompatibility; the missing test baseline is the more direct control.

## Not audited

- No live Ollama, network, Playwright, email, YouTube, or wiki-root integration run was performed.
- Dependency advisories and current upstream versions were not checked.
- The contents of external legacy source packages referenced by `SKILL.md` were not audited.
- Existing user changes were inspected but not modified; findings describe the current working tree, not only commit `994e4f6`.

## Suggested planning selection

Turn findings 2-4 into implementation plans first, bundling focused regression tests with findings 2 and 3. Grow finding 1 in parallel. Finding 5 can proceed independently. Split finding 6 into small, evidence-backed plans by subsystem rather than attempting a blanket rewrite.
