# Knowledge Wiki Skill Audit

Date: 2026-07-11  
Scope: current working tree, including uncommitted changes  
Mode: standard, read-only source audit

## Executive assessment

The skill has a coherent product boundary and unusually useful operational knowledge, but it is not yet safely portable. The highest-leverage work is to establish automated tests around filesystem mutation, then close two unsafe path-handling behaviors. The packaged default configuration also leaks a personal filesystem layout and contradicts the README.

## Recommended order

1. Establish deterministic characterization tests using temporary wiki roots and mocked network/Ollama/subprocess boundaries.
2. Change `--images-dir` ownership semantics and cover both copy and cleanup behavior.
3. Add a single category/path validation boundary and apply it to CLI, feed, asset, and duplicate-check paths.
4. Replace the personal config default.
5. Refactor `SKILL.md`: keep routing, invariants, canonical commands, and live pitfalls; move incident history to `references/troubleshooting.md`.
6. Tighten exception handling incrementally, starting with ingest and transcript fallbacks covered by tests.

Dependency note: finding 1 should land before findings 2, 3, and 6.

## Direction options

- **Make the skill self-validating.** A small offline `scripts/skill_doctor.py` could validate configuration resolution, dependencies, Ollama reachability, writable wiki layout, and optional browser tooling without ingesting content. This is strongly grounded in the repeated setup and split-brain troubleshooting in `README.md` and `SKILL.md`.
- **Separate agent routing from operator troubleshooting.** Keep `SKILL.md` compact and link to focused references for Substack, YouTube, email, and recovery scenarios. The repository already has those references, so this mainly removes duplication and lowers instruction ambiguity.

## Considered and rejected

- Arbitrary URL fetching was not reported as SSRF: this is a user-invoked local ingestion CLI whose core purpose is fetching supplied URLs.
- Subprocess use was not reported as command injection: inspected calls use argument arrays and do not set `shell=True`.
- Unpinned dependency upper bounds were not prioritized without evidence of a current incompatibility; the missing test baseline is the more direct control.

## Not audited

- No live Ollama, network, Playwright, email, YouTube, or wiki-root integration run was performed.
- Dependency advisories and current upstream versions were not checked.
- The contents of external legacy source packages referenced by `SKILL.md` were not audited.
- Existing user changes were inspected but not modified; findings describe the current working tree, not only commit `994e4f6`.

## Suggested planning selection

Turn findings 1-4 into implementation plans first. Finding 5 can proceed independently. Finding 6 should be split into small, test-backed plans by subsystem rather than attempted as one blanket rewrite.
